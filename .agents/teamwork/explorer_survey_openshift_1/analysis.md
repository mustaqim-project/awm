**Target Mobile Repository**: `C:\laragon\www\cooca_my_own`  
**Target Backend Repository**: `C:\laragon\www\cooca_core`  
**Live Production API**: `https://cooca.id` (Single Source of Truth)  
**Investigation Date**: 2026-11-03  
**Auditor**: `explorer_survey_openshift_1` (Teamwork Exploration Agent)

## Executive Summary

A comprehensive, read-only architectural and code-level investigation into the OpenShift lifecycle across Flutter mobile (`cooca_my_own`), backend contracts (`cooca_core`), and live production (`https://cooca.id`) revealed **seven critical root causes** that cause OpenShift failures, false-positive success states, session hijacking between cashiers, cache wiping on network dropouts, and drawer float mismatches.

Most notably, a severe logic flaw in Flutter's `PosService` (`pos_service.dart`) causes **every HTTP error (400, 401, 404, 422, 500) to be classified as a successful operation** because error maps generated by `ApiClient._processResponse` contain `'data': null`, which satisfies `response.containsKey('data')`. Consequently, when backend returns validation errors (such as invalid `location_id`), the app displays a green success SnackBar, pops the shift modal, but leaves the shift closed—locking the cashier out of POS transactions.

Furthermore, backend `PosShiftService::getActiveShift()` unconditionally returns the first open shift in the location (`return $query->first();`) if the current user has no open shift. This causes **cashiers on separate devices to hijack other cashiers' shifts**, prevents new shifts from opening, and allows one cashier to close another cashier's drawer remotely.

## 2. Seven Critical Root Causes of OpenShift Failures

### Root Cause 1: Misclassification of HTTP Failure Responses as Success (The `containsKey('data')` Trap)

**Files**: 
- `c:\laragon\www\cooca_my_own\lib\core\services\api_client.dart` (Lines 220–228)
- `c:\laragon\www\cooca_my_own\lib\core\services\pos_service.dart` (Lines 41, 67, 416, 439)
- `c:\laragon\www\cooca_my_own\lib\state\merchant_state.dart` (Lines 1809–1818)
- `c:\laragon\www\cooca_my_own\lib\screens\pos\pos_shift_modal.dart` (Lines 179–194)

#### Mechanism:
In `ApiClient._processResponse(http.Response response)`:
```dart
      if (response.statusCode >= 200 && response.statusCode < 300) {
        return decoded;
      }
      return {
        'success': false,
        'statusCode': response.statusCode,
        'message': decoded is Map && decoded.containsKey('message')
            ? decoded['message']
            : 'Terjadi kendala server (Kode: ${response.statusCode})',
        'errors': decoded is Map ? decoded['errors'] : null,
        'data': decoded is Map ? decoded['data'] : null, // <-- ALWAYS INJECTS 'data': null
      };
```
Whenever any HTTP error occurs (e.g., 401 Unauthenticated, 403 Forbidden, 422 Unprocessable Entity, 500 Internal Server Error), `_processResponse` creates a Map that explicitly includes `'data': null`.

Now observe `PosService.openShift()`:
```dart
    final response = await _api.post('/api/v1/pos/shifts/open', body: body);
    if (response is Map && (response['success'] == true || response.containsKey('shift') || response.containsKey('data'))) {
      final shiftData = response['data'] ?? response['shift'];
      return {
        'success': true, // <-- EXECUTED ON HTTP 422 / 500!
        'data': shiftData, // null!
        'shift': shiftData, // null!
        'message': response['message'] ?? 'Shift kasir berhasil dibuka.',
      };
    }
```
Because `response.containsKey('data')` is `true`, `PosService.openShift()` assumes the call succeeded. It returns `{'success': true, 'data': null, 'message': 'The selected location id is invalid.'}`.

In `MerchantState.openShift()`:
```dart
    if (res['success'] == true) {
      final sData = res['data'] ?? res['shift'];
      if (sData != null && sData is Map) {
        activeShift = PosShift.fromJson(Map<String, dynamic>.from(sData));
        ...
      }
      // sData is null, so activeShift remains NULL!
      await refreshPosCatalog();
      return {'success': true, 'message': res['message'] ?? 'Shift kasir berhasil dibuka.'};
    }
```
In `PosShiftModal._handleShiftAction()`:
```dart
      final res = await widget.state.openShift(
        openingCash: _enteredCash,
        notes: _notesController.text.trim(),
      );
      final success = res['success'] == true; // TRUE!
      if (mounted) {
        setState(() => _isLoading = false);
        Navigator.pop(context); // POPS THE MODAL!
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(
            backgroundColor: success ? const Color(0xFF34C759) : const Color(0xFFFF3B30), // GREEN!
            content: Text(res['message']?.toString() ?? ...), // "The selected location id is invalid."
          ),
        );
      }
```
#### Impact:
The modal closes, a **green SnackBar** displays an error message ("The selected location id is invalid." or "No active business context selected"), but `activeShift` is **null**. When the cashier tries to checkout, they receive: *"Shift kasir belum dibuka. Silakan buka shift terlebih dahulu."*

The exact same fatal bug exists in `closeShift()`, `recordCashMovement()`, `recordExpense()`, and `bootstrapTerminal()`.

### Root Cause 2: Destruction of Local Active Shift Cache on Network Dropout

**Files**:
- `c:\laragon\www\cooca_my_own\lib\core\services\pos_service.dart` (Lines 389–401)
- `c:\laragon\www\cooca_my_own\lib\screens\pos\pos_shift_modal.dart` (Lines 78–94)

#### Mechanism:
In `PosService.getActiveShift()`:
```dart
  Future<Map<String, dynamic>> getActiveShift({String? locationId}) async {
    final params = locationId != null ? {'location_id': locationId} : null;
    final response = await _api.get('/api/v1/pos/shifts/active', queryParams: params);
    if (response is Map) {
      final rawShift = response['active_shift'] ?? response['shift'] ?? response['data'];
      return {
        'success': true, // <-- RETURNS TRUE ON NETWORK FAILURE!
        'active_shift': rawShift, // null!
        'summary': response['summary'],
      };
    }
    return {'success': false, 'active_shift': null};
  }
```
When offline or during a network dropout, `_api.get` catches a timeout/socket exception and returns:
`{'success': false, 'message': 'Koneksi ke server gagal: SocketException...'}`.
Because `response is Map` is `true`, `PosService.getActiveShift()` ignores `response['success'] == false`, extracts `rawShift = null`, and returns:
`{'success': true, 'active_shift': null}`!

Now look at `PosShiftModal._initShiftData()`:
```dart
      final activeRes = await _posService.getActiveShift(locationId: widget.state.selectedLocationId);
      if (activeRes['success'] == true) {
        final raw = activeRes['active_shift'];
        if (raw is Map) {
          ...
        } else {
          // EXECUTED ON NETWORK FAILURE!
          widget.state.updateActiveShift(null);
          await LocalStorageService().setCachedPosActiveShift(null); // PURGES PERSISTENT CACHE!
        }
      }
```
#### Impact:
A momentary network blip or opening the Shift Modal while offline **permanently deletes the active shift from local storage**. The cashier is immediately locked out of offline sales because `state.hasActiveShift` becomes `false`.

### Root Cause 3: Cross-Cashier Shift Hijacking in Backend `PosShiftService`

**Files**:
- `c:\laragon\www\cooca_core\app\Domain\Pos\PosShiftService.php` (Lines 21–36)
- `c:\laragon\www\cooca_core\app\Http\Controllers\Api\V1\Pos\PosShiftController.php` (Lines 65–94)

#### Mechanism:
In `PosShiftService::getActiveShift()`:
```php
    public function getActiveShift(Business $business, User $user, ?string $locationId = null): ?PosShift
    {
        $query = PosShift::where('business_id', $business->id)
            ->where('status', PosShift::STATUS_OPEN);

        if ($locationId) {
            $query->where('location_id', $locationId);
        }

        $userShift = (clone $query)->where('user_id', $user->id)->first();
        if ($userShift) {
            return $userShift;
        }

        return $query->first(); // <-- FATAL UNCONDITIONAL FALLBACK!
    }
```
If Cashier B logs into the app at Location 1 while Cashier A already has an open shift at Location 1:
1. `$userShift` for Cashier B is `null`.
2. Line 35 executes: `return $query->first();`, which returns **Cashier A's open shift**.
3. `PosShiftController::current()` sends Cashier A's shift to Cashier B's mobile app.
4. Cashier B's app marks `activeShift` as active.
5. Cashier B's modal displays: *"STATUS SHIFT KASIR: Sedang Dibuka"*, displaying Cashier A's cash drawer balance and Cashier A's float.
6. Cashier B **cannot open their own shift**.
7. If Cashier B taps *"Tutup Shift Sekarang"*, **Cashier A's shift is terminated remotely** from Cashier B's device!
8. If Cashier B performs sales, all sales are credited to Cashier A's shift ID (`pos_shift_id`), contaminating audit logs and cash reconciliation.

### Root Cause 7: Stale / Cross-Tenant Location Validation Errors

**Files**:
- `c:\laragon\www\cooca_core\app\Http\Controllers\Api\V1\Pos\PosShiftController.php` (Lines 126–132, 144–151)
- `c:\laragon\www\cooca_my_own\lib\state\merchant_state.dart` (Lines 757, 1186–1196, 1807)

#### Mechanism:
In `PosShiftController.php`:
```php
        $validated = $request->validate([
            'location_id' => ['nullable', 'string', 'exists:locations,id'],
        ]);
```
The validation checks `exists:locations,id` globally across the database, but does not enforce that the location belongs to `$business->id`.
If `selectedLocationId` stored in Flutter's `LocalStorageService` is stale from a previous tenant session, or points to a non-existent location ID:
1. If the ID does not exist in `locations`, validation returns HTTP 422: `The selected location id is invalid.`
2. Due to Root Cause 1, Flutter treats this 422 as a success, shows a green SnackBar with the error text, and leaves the cashier with `activeShift = null`.

## 4. Specific Remediation Plan

### Remediation Item 1: Fix Response Parsing in `PosService` and `ApiClient`
In `cooca_my_own/lib/core/services/pos_service.dart`:
- Replace all instances of `(response['success'] == true || response.containsKey('data'))` with strict validation:
  ```dart
  if (response is Map &&
      response['success'] != false &&
      response['statusCode'] == null &&
      (response['success'] == true || response['data'] != null || response['shift'] != null))
  ```
- Specifically in `getActiveShift()`:
  ```dart
  if (response is Map && response['success'] != false && response['statusCode'] == null) {
    final rawShift = response['active_shift'] ?? response['shift'] ?? response['data'];
    return {
      'success': true,
      'active_shift': rawShift,
      'summary': response['summary'],
    };
  }
  return {
    'success': false,
    'message': response?['message'] ?? 'Gagal memuat status shift kasir.',
    'active_shift': null,
  };
  ```

### Remediation Item 2: Protect Local Shift Cache on Network Dropout
In `cooca_my_own/lib/screens/pos/pos_shift_modal.dart`:
- Update `_initShiftData()` to only wipe cache when backend explicitly confirms `active_shift: null` with HTTP 200:
  ```dart
  if (activeRes['success'] == true) {
    final raw = activeRes['active_shift'];
    if (raw is Map) {
      final liveShift = PosShift.fromJson(Map<String, dynamic>.from(raw));
      widget.state.updateActiveShift(liveShift);
      await LocalStorageService().setCachedPosActiveShift(Map<String, dynamic>.from(raw));
    } else {
      widget.state.updateActiveShift(null);
      await LocalStorageService().setCachedPosActiveShift(null);
    }
  } else {
    // Offline or network error: Preserve cached active shift!
    final cached = LocalStorageService().getCachedPosActiveShift();
    if (cached != null) {
      widget.state.updateActiveShift(PosShift.fromJson(cached));
    }
  }
  ```

### Remediation Item 3: Fix Cashier Shift Isolation in Backend `PosShiftService`
In `cooca_core/app/Domain/Pos/PosShiftService.php`:
- Prevent returning another user's shift to a regular cashier:
  ```php
    public function getActiveShift(Business $business, User $user, ?string $locationId = null): ?PosShift
    {
        $query = PosShift::where('business_id', $business->id)
            ->where('status', PosShift::STATUS_OPEN);

        if ($locationId) {
            $query->where('location_id', $locationId);
        }

        $userShift = (clone $query)->where('user_id', $user->id)->first();
        if ($userShift) {
            return $userShift;
        }

        // Only allow managers/supervisors/owners to inspect other active shifts if explicitly requested
        $membership = \App\Models\BusinessMembership::where('user_id', $user->id)
            ->where('business_id', $business->id)
            ->first();
        $isSupervisor = in_array(strtolower((string) ($membership?->role ?? '')), ['owner', 'admin', 'manager'], true);

        if ($isSupervisor) {
            return $query->first();
        }

        return null; // Return null so regular cashier can open their own shift!
    }
  ```
